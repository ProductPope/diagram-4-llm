# 0007. shadcn/ui on Tailwind CSS for everything except the map

Status: Accepted
Date: 2026-10-07

## Context

The phase 1 interface used unstyled browser controls with a few hand-written
rules. The maintainer asked for a modern, consistent look for the parts of
the app that are not the diagram (sidebar, reading pane, composer, settings
and the onboarding that follows), and named shadcn/ui.

Two constraints from earlier decisions shape the choice:

- **Strict Content Security Policy** (ARCHITECTURE section 7). Styles may
  come only from the app's own files: no inline `<style>` elements and no
  `style` attributes in markup. Styles set from JavaScript through the CSSOM
  are allowed, which is how React Flow and Radix position elements.
- **Small, auditable dependencies.** Code that the project ships should be
  readable in the repository where practical.

shadcn/ui is not a package. Its command line tool copies component source
files into the project, built on Radix primitives and styled with Tailwind
CSS utility classes and CSS variables for colours.

## Decision

- Use shadcn/ui with the Radix base and the "nova" preset, on Tailwind CSS
  4 through its Vite plugin. Components live in `apps/web/src/components/ui`
  as generated by `shadcn add`, with one change: they import the two Radix
  primitives they need (`@radix-ui/react-slot`, `@radix-ui/react-label`)
  directly instead of through the `radix-ui` package, which re-exports the
  same modules but installs about sixty primitives. Only components the app
  uses are kept. The `shadcn` command line tool is run with `pnpm dlx` at a
  pinned version and is not a dependency: it has more than thirty
  dependencies of its own, and the stylesheet it offers defines only
  variants and animations that these components do not use.
- Import them through `package.json#imports` (`#components/*`, `#lib/*`),
  one of the two alias setups the shadcn documentation describes. It needs
  no bundler alias, because Vite and TypeScript resolve package imports
  natively.
- **Exclude components that inject inline styles**, because the CSP blocks
  them: Radix Dialog, Sheet, Alert Dialog, Select and modal menus lock page
  scrolling with an injected `<style>` element, and Scroll Area injects one
  to hide native scroll bars. Native elements are used instead: `<select>`
  through shadcn's `native-select`, `<details>` for disclosure, and panels
  instead of modal dialogs. The main end-to-end test, which goes
  through settings, the composer, the reading pane and the map against
  the production build, fails on any console error, including a CSP
  violation.
- **The map keeps its own styles.** React Flow renders the map's DOM, so it
  is styled through React Flow's CSS variables, mapped to the design
  tokens, plus a few rules for the node buttons. These rules sit outside
  CSS cascade layers, because React Flow's stylesheet is unlayered and
  unlayered rules always win over layered ones.
- The app follows the system colour scheme (`prefers-color-scheme`); there
  is no theme switch. One token is added to the preset: `--branch`, the
  colour of the selected branch on the map. One is changed: `--ring` is
  the foreground colour, because the preset's grey, drawn at half opacity
  by the components, gives focus rings a contrast below the 3:1 of WCAG
  1.4.11.
- The Geist font is bundled from `@fontsource-variable/geist`, so no font
  is loaded from a third party at runtime.

## Alternatives considered

- **Keep hand-written CSS.** No dependencies, but a consistent, accessible
  set of controls is a large amount of work that shadcn/ui has already done.
- **A packaged component library (MUI, Mantine, Chakra).** Larger runtime,
  styling through a library-specific API, and the components cannot be
  read or changed in the repository. MUI and Chakra also inject styles at
  runtime, which the CSP forbids.
- **Relax the CSP to allow inline styles** so every shadcn component works.
  Rejected: injected styles can leak data from the page through CSS
  selectors, and the page holds the user's API key.

## Consequences

- New runtime dependencies: `@radix-ui/react-slot` and
  `@radix-ui/react-label`, `class-variance-authority`, `cn` (shadcn's
  class-name merger), `lucide-react` icons (tree-shaken) and the Geist
  font. Build-time only: `tailwindcss` and `@tailwindcss/vite`. Measured on
  the production build: the JavaScript bundle grew from 262 kB to 282 kB
  gzipped and the stylesheet from 4 kB to 10 kB gzipped; the Latin font
  file is 29 kB.
- Adding a shadcn component requires checking that it does not inject
  styles, and covering it in an end-to-end test that checks the console.
- Generated component files are reformatted by Prettier and their Radix
  imports are narrowed as described above; they are otherwise left as
  generated. A component added later may need `tw-animate-css` or shadcn's
  stylesheet; it is added then, with the component that uses it.
